# Code of conduct

## The short version

Be decent. Assume the other person is trying to build something good. Disagree about the work, not
about the person.

## What we expect

- Technical criticism is welcome and wanted — of code, designs, claims and measurements.
- Personal attacks, harassment, sexual attention, demeaning jokes about who somebody is, and
  deliberate intimidation are not.
- Publishing somebody's private information without their explicit permission is not, and in this
  project it is close to unforgivable: Varyz exists because private information should stay where
  its owner put it.
- If you are asked to stop something, stop. You can disagree afterwards.

## Personal data

This project handles people's archives. Two rules that are ordinary elsewhere are strict here:

- **Never paste real personal content into an issue, a pull request, a commit, a test fixture or a
  discussion** — not yours and certainly not anyone else's. Synthesise it.
- **Never ask a reporter for their archive.** If a bug needs data to reproduce, the maintainers'
  job is to find a synthetic reproduction, not to collect somebody's life.

Breaking either of these is a code-of-conduct matter, not just a review comment.

## Scope

This applies in the project's own spaces — repository, issues, pull requests, discussions — and
whenever someone is representing the project publicly.

## Enforcement

Report through [GitHub's private vulnerability reporting](https://docs.github.com/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)
on this repository — the same private channel as a security report, for the same reason: it stays
private, and no maintainer's personal mailbox is the front door. Say plainly that it is a conduct
report. If you cannot use GitHub, open a public issue saying only "conduct report, please contact
me", with no detail, and a maintainer will arrange a private channel.

Maintainer: **Egor Menshikov**.

Reports are handled privately. The maintainers will respond as promptly as one person reasonably
can, will keep the reporter's identity confidential, and will say what they decided. Consequences
range from a private word, through a warning, to a temporary or permanent ban from the project's
spaces. Maintainers who break these rules are held to them more strictly, not less.
